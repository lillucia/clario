# Web 学习模式

Web 学习模式提供“开始学习、知识库、技能管理、学习状态、学习计划、工作区与练习”入口，设置页保留通用、模型和记忆设置。它使用原有聊天、三层记忆和工作区流程，不需要迁移学习数据。

## 开启与生效

在实际使用的 Inno `config.json` 顶层加入：

```json
{
  "experience": "learning"
}
```

这是配置片段，请只修改这个字段，保留原有模型、凭据、路径和其他设置。

- `"learning"`：启用精简 Web 学习模式。
- `"full"`：使用完整模式，按各项原有设置启用功能。
- **已有配置缺少 `experience` 时，继续按 `full` 运行。**
- 仓库的 [`config.example.json`](../config.example.json) **显式使用 `learning`**；复制示例不会改变旧配置的缺省行为。
- 其他取值会报配置错误，不会静默切换模式。

模式在服务初始化时读取。修改后按原服务管理方式重启，再重新加载浏览器页面；没有在线修改 `experience` 的设置接口。若更新了代码，先运行 `npm run build`。重启应等待当前对话和待回答卡片处理完毕，并继续使用原启动命令中的 `--home`、`--config`、`--data-dir`、`--workspace` 等路径。

Web 服务采用延迟初始化，`/health` 返回成功还不能确认当前模式。读取 `GET /api/settings` 后，其顶层 `experience` 应为 `learning`。隔离验收环境的准备与启动方法见 [基线说明](baseline/README.md)。

## 生效范围

| 能力 | `learning` 下的行为 |
| --- | --- |
| 模型配置、聊天、SSE、提问卡与历史会话 | 保留原流程 |
| L1 学习目标、状态、证据与教学入口 | 保留；尊重原 L1 开关 |
| L2 归档、查询、结构检查 | 保留；尊重原 L2 开关 |
| L3 跨会话检索 | 保留；尊重原 L3 开关 |
| 工作区、附件、文档解析、OCR、练习与运行记录 | 保留原流程及各自的配置要求 |
| 技能管理、学习计划 | 开放侧栏入口、页面直达及聊天 `/skills`、`/jobs` 快捷项；沿用原技能与定时任务后端 |
| 权限系统 | 保留原启用状态与策略，默认启用；模式不会覆盖原策略 |
| 飞书、微信、QQ 等消息渠道与桥接 | 不注册或启动渠道；阻止扫码登录、渠道操作及桥接消息 |
| subagents、MCP、todo、webAccess、computerUse | 不加载对应复杂扩展，即使原配置为 `enabled: true` |
| Electron 桌面入口 | 使用 `learning` 配置时，在监听端口前明确报错；桌面应使用独立的 `full` 配置 |

这些限制由后端执行，不能通过直接调用相应设置接口绕过。原模块和源码保留，恢复完整模式无需重新实现功能。

调度器、终端和技能管理等原有后端能力继续保留。技能管理可上传、导入、编辑和启停技能；学习计划可创建、编辑、启停任务、立即执行并查看记录。学习计划沿用原定时任务页面，与“工作区与练习”入口并存；定时执行仍依赖后端服务持续运行。原生 Tavily `web_search` 也仍遵循原凭据配置，它与被关闭的 `pi-web-access` 扩展不同。模式开关用于收拢产品能力，不替代权限系统或操作系统沙箱。

## 首页与学习目标

首页沿用原版的居中对话输入框、预设空间卡片和柔和背景光晕。无需先填表：直接描述想学什么，目标不明确时由代理通过对话追问。首页预设复用既有工作区模板；首次读取允许回退到随项目提供的模板，手动刷新仍会提示远端错误。

详细目标表单位于“学习状态”学习者面板的“学习目标”区，通过“填写详细目标”补充标题、类型、状态、优先级及达成标准；已有目标也可编辑。表单继续调用原 L1 API，不创建另一套目标数据。保存失败保留草稿并在弹窗内提示，达成标准支持多行输入。

首页不再预先创建目标或拼装强制教学提示。用户原话直接进入聊天；后端沿用 `record_learning_event` / `goal_declared` 的目标记录与投射流程，遵守 L1 开关、证据和来源契约。详细表单手工新增的目标仍由后端标为 `user_declared`，既有目标的来源不因编辑改变。

教学仍走原来的必要前置知识检查、简短讲解、作答与反馈流程。声明目标、阅读材料或听过讲解都不能单独证明掌握；学习状态更新应以实际作答和相应证据为依据。

## 材料从聊天输入框加入

| 材料来源 | 操作 |
| --- | --- |
| 本机文件 | 点击输入框的“＋”选择本机文件，或直接拖入、粘贴文件；发送时上传到当前工作区并关联到消息。 |
| 图片 | 使用输入框图片按钮或粘贴图片，沿用原生图像 / OCR 能力。 |
| 工作区文件 | 在“＋”菜单选择当前工作区已有文件，无需重复上传。 |
| 文本 | 直接粘贴到输入框；长文本显示为粘贴内容块，随消息发送。 |
| 已有知识库材料 | 在对话中说明要使用的主题或页面，由代理沿用 `l2_query` 查询；知识库页面入口保留。 |

输入框下方保留原工作区选择器。默认临时工作区也是实际目录，当前实现不会在删除会话时自动清理；长期学习可选择已有工作区或新建工作区。单文件上限继续为 32 MB。

学习模式下，材料上传失败时整条消息暂不发送：文字和附件保留，可以重试失败附件或移除后发送。已成功上传的文件在重试时直接复用。会话创建失败不会误发至旧会话，上传期间切换页面或会话也不会自动把旧草稿发送到新会话。

上传成功只证明文件已保存；代理是否读取、解析或引用，应核对聊天中的工具执行结果。**上传或粘贴不等于完成 L2 归档。** 需要长期收入知识库时，明确要求归档，并确认 `l2_archive` 成功。

先前的 `LearningStart.tsx`、`learning-start.ts` 及相关样式/测试源码保留作比较，但已不挂载到首页。本轮入口调整前的文件快照位于 `runtime/ui-homepage-20261004/before/`；回退入口时不覆盖学习数据。

## 保留的数据与工具契约

切换模式不会删除或重新创建学习者画像、目标、证据、L2 原始件和 Wiki、历史会话及 trace、工作区文件、练习运行记录。数据继续由原路径与原 API 管理，没有新增一套“学习模式数据库”。

后端区分存储配置和有效配置：学习模式只在运行时把受限功能视为关闭，**不把原来的 `enabled: true` 永久改成 `false`**。修改模型、记忆或主题等仍可用的设置时，也基于存储配置保存，从而保留完整模式的原有偏好。

`GET /api/settings` 返回的是**脱敏后的有效视图**，不是可直接回写的配置备份。不要用它的响应覆盖 `config.json`，否则可能把掩码状态或脱敏凭据当成真实配置。

原有工具结果含义保持不变，例如：

- `l2_archive.reviewCount` 是归档生成的待审阅建议数；结果中的 `reviewSource: "archive_generation"`、`lintPerformed: false` 明确说明归档未执行 lint。
- 只有实际成功执行 `l2_lint`，其结果才标记 `lintSource: "l2_lint"`、`lintPerformed: true`。
- 练习记录中的退出码 0 表示命令正常结束，不能单独证明学习者掌握了知识。
- L3 沿用每次 `turn_end` 的增量索引流程，不需要通过删除或关闭会话触发。

## 接口核对

学习模式下，可用以下只读请求检查实际状态：

| 请求 | 应返回的关键状态 |
| --- | --- |
| `GET /api/settings` | `experience: "learning"`；已配置渠道的 `enabled`、`subagents.enabled`、`mcp.enabled` 及 `plugins.todo/webAccess/computerUse.enabled` 为 `false` |
| `GET /api/channels` | 空数组 |
| `GET /api/mcp` | `enabled: false`、`adapterLoaded: false`、`servers: []`、`status: null`；不读取共享 MCP 定义 |

`computerUse.enabled` 表示有效状态；`computerUse.explicit` 保留用户原来的显式选择，因此学习模式中可能同时出现 `enabled: false` 和 `explicit: true`。

对渠道、computer use、MCP、web access 的受限设置写入，以及 MCP 服务管理写入，会返回 HTTP 403，错误码为 `experience_restricted`。渠道操作还覆盖会产生副作用的扫码轮询 GET 请求和 `/api/bridge/*`，而不是只阻止设置页上的开关。

对应回归测试位于 [配置测试](../apps/clario/src/config.experience.test.ts)、[路由测试](../apps/clario/src/server/routes/experience.test.ts) 和 [实际扩展加载测试](../apps/clario/src/agent/learning-experience.test.ts)。测试数量和完整基线结果以当前执行报告为准。

## 回退到完整模式

1. 等待进行中的对话、练习及确认卡片处理完毕。
2. 在同一个实际配置文件中把 `experience` 改为 `"full"`。删除该字段也会恢复兼容缺省值，但显式写 `full` 更便于辨认。
3. 沿用原数据和工作区路径重启服务，再刷新页面。
4. 检查 `GET /api/settings` 的 `experience` 为 `full`，确认原有界面入口与保存的功能开关恢复。

完整模式按各功能原来保存的配置启用；原来显式关闭的功能仍然关闭。渠道连接、MCP 服务等是否成功启动，还取决于原凭据、依赖与外部服务状态。回退不需要删除数据、清空工作区、重置画像或覆盖整个配置文件。
